# SOP — 体育数据运营日报(AI 工作流版)

> 把「每天早上人工拼日报」标准化为一条可复用、可调度、可交接的 AI 工作流。
> 适用对象:体育运营、数据、风控。维护人:AI 业务流程优化负责人。版本:v1.0。

---

## 0. 为什么要做这条 SOP

| | 改造前(人工) | 改造后(AI 工作流) |
|---|---|---|
| 拉数据 | 手动登 3 个后台导 CSV | 定时 API 自动拉,统一结构 |
| 看异动 | 肉眼扫赔率表,靠经验 | 规则引擎自动命中 + 排序 |
| 写日报 | Excel 截图 + 手打结论 | LLM 按固定口径自动撰写 |
| 推送 | 复制贴群,易漏 | Webhook 自动推飞书/Slack |
| 耗时 | 约 60-90 分钟/天/人 | 约 3-5 分钟/天(只做复核) |
| 一致性 | 因人而异、口径漂移 | 模板固定,口径不漂 |

「节省工时」按团队 1 人 × 75 分钟/天 × 22 工作日 ≈ **27.5 小时/月**,且夜班/周末不漏报。

---

## 1. 触发条件

- 定时:每日 08:30(开市后)与赛前临场两次。可在 n8n Cron 节点改频率。
- 手动:运营临时需要时,跑 `python run_pipeline.py --date YYYY-MM-DD`。

## 2. 流程步骤(位·埋·时·测·传·表·统)

| 步骤 | 做什么 | 工具/脚本 | 产出 | 失败兜底 |
|---|---|---|---|---|
| S1 取数 | 拉赛事赔率 + 投注分布快照 | `fetch_odds.py`(真实环境换 API) | `odds_snapshots_<date>.json` | API 失败重试 3 次,仍失败告警不出报 |
| S2 检测 | 规则引擎命中异动并按严重度排序 | `detect_anomaly.py` | `anomalies_<date>.json` | 阈值集中在 THRESHOLDS,可热改 |
| S3 撰写 | LLM 按模板口径生成日报 | `generate_report.py` + `prompt_日报生成.md` | `report_<date>.md` | 无 key/LLM 失败 → 离线模板兜底 |
| S4 推送 | 推飞书/Slack/邮件 | n8n Webhook 节点 | 群消息 | 推送失败重试 + 落本地存档 |
| S5 复核 | 人工只看高优先盘口,确认/转风控 | 人 | 处置记录 | 高优先未处置 30 分钟二次提醒 |

## 3. 规则阈值(运营可自助调)

| 规则 | 含义 | 默认阈值 | 严重度 |
|---|---|---|---|
| R1 赔率急跌 | 某边较开盘跌幅 | >15% | 高 |
| R2 反向线动 | 钱压一边但该边赔率反升 | 投注≥65% 且赔率升≥10% | 高 |
| R3 投注集中 | 单边投注占比 | >80% | 中 |
| R4 大额盘口 | 单场投注额 | >12 万 USDT | 中 |
| R5 少笔大额 | 大额但笔数极少(疑大户/对打) | 额≥6 万且 <200 笔 | 高 |

## 4. 质量判准(怎么算这条工作流「跑对了」)

- 取数完整性:赛事数与后台一致,缺口 >5% 不出报。
- 异动召回:人工抽查高优先盘口,漏报率目标 <5%。
- 日报口径:无 emoji、数字可回溯、异动不擅自定性(措辞为「疑似/建议核查」)。
- 时效:08:30 触发后 10 分钟内出报。

## 5. 交接与培训要点

- 改口径 → 只动 `prompt_日报生成.md`,不碰代码。
- 改异动敏感度 → 只动 `detect_anomaly.py` 顶部 `THRESHOLDS`。
- 接真数据 → 只换 `fetch_odds.py` 的 `fetch_snapshots()`,返回结构不变,下游零改动。
- 这条 SOP 是模板:换成「用户工单分类」「运营周报」只需替换 S1 取数源 + S2 规则 + S3 提示词,骨架复用。
